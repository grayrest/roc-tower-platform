# Plan: Typed SQL — inline-SQL codegen + cursor FFI (v2, post-review)

## Summary

Replace the materialized `sqlite_exec!` path with a cursor FFI (one copy per
cell on the generated path, no runtime name scans) and add `crates/sqlgen`, a
codegen tool that scans `## @sql`-marked inline SQL in app modules, types it
with an owned VDBE bytecode analyzer against `## @schema` DDL, and emits
per-module Roc twins with typed read functions and pure `DbWrite` effect
builders.

Design of record: `memory/tower-platform-sqlgen-design.md` (grill-me
2026-07-13 + post-review amendments). v1 of this plan was adversarially
reviewed by three independent agents; all findings are folded in below.
API stability with existing examples is explicitly a non-goal.

## Decision log (review round, all user-approved)

1. `sql_col_type!` storage-class probe added (replaces `sql_col_is_null!`).
2. `Sql.query!` materializes rows internally → **handles never escape a
   function frame**; pure, expect-testable by-name decode preserved
   (TypeMismatch via the probe). Generated path streams, zero intermediates.
3. `@sql` queries MUST use named `:params` (tool errors on `?`); names from
   SQL, types from analyzer, `@params` only on inference failure. Dynamic
   path keeps `?`.
4. `## @fragment` marker + scan-time `${Name}` splicing (same module,
   top-level, fragments only) — `article_select` stays single-source.
5. Generated records are FLAT; thin hand mappers (row → nested JSON shape)
   survive in app code; `as`-pin dropped from v1.
6. Teardown hardening: CtxGuard moves into a reaper task that awaits the
   blocking JoinHandle — ctx sweep can never race the handler thread
   (also fixes the latent memo-thunk race). Finish-on-all-arms remains the
   leak policy inside `query!`/generated readers.
7. Microbench go/no-go after Phase 2, before any migration.
8. Analyzer spike runs in a worktree; only the survivor lands.
   `sqlite3_libversion()` hard-asserted in the tool.
9. Glue-spike all hosted signatures before host Rust;
   `sql_step! : U64 => Try(Bool, Str)` (proven shapes only).
10. Phase 6 bench: reuse 2026-07-12 seed harness (5k/200/10k) + wrk baseline,
    anonymous endpoints, bar = no endpoint regresses >2% AND article-list
    p50 measurably improves.

## Impact

- **Modify:** `platform/Host.roc`, `platform/main.roc`, `platform/Sql.roc`,
  `platform/Req.roc` (reserved_id! — write-with-RETURNING via the cursor
  path; `sql_begin!` is deliberately write-capable),
  `crates/host/src/{effects.rs,router.rs,ffi_tests.rs,types.rs}`,
  `Cargo.toml`, `Justfile`, `.gitignore`,
  `examples/realworld/{main,Db,Users,Articles,Profiles,Comments,Auth}.roc`,
  `examples/e2e/main.roc`, `examples/hello/main.roc`,
  `crates/e2e-tests/tests/*.rs` (ctx_registry_size timing + rewritten routes).
  (~27 `sqlite_exec!` call sites across 8 files; ctxmemo has none.)
- **Create:** `crates/sqlgen/` (`main.rs`, `scan.rs`, `analyze.rs`, `emit.rs`,
  `tests/`), `platform/NullableI64.roc` (+ siblings as needed, exposed in
  main.roc), generated `examples/realworld/*Gen.roc` (committed),
  `notes/<date>-typed-sql-bench.md`.
- **Risks:**
  - Analyzer port is the long pole (~53 opcodes incl. coroutines/subroutines
    for realworld reads; `favorites_count NOT NULL` needs path-sensitive
    analysis). Phase 1 kill criterion; pivot = decltype + mandatory alias
    annotations; Phases 2–6 survive the pivot.
  - `rusqlite::Statement` is !Send and borrows Connection → suspended cursors
    use raw `sqlite3_stmt` handles via `Connection::handle()` + a hand-rolled
    per-connection statement cache. Isolated in one module.
  - Glue fragility: two known compiler glue bugs → Phase 2 opens with the
    signature spike; shapes restricted to proven forms.
  - Router teardown change (reaper) alters ctx_registry_size timing —
    e2e/ffi tests updated deliberately, not incidentally.

## Phases

Phase 1: Analyzer spike (WORKTREE) — files: `crates/sqlgen/{Cargo.toml,src/main.rs,src/analyze.rs,tests/analyze.rs}`, root `Cargo.toml` — est. ~1,200 lines in-worktree; only the survivor merges
  - Bin crate on workspace `rusqlite` (bundled ⇒ same SQLite as host);
    hard assert on `sqlite3_libversion()` at startup.
  - `analyze.rs`: EXPLAIN register-dataflow walker for column type +
    nullability + best-effort param types. Unknown opcode ⇒ hard error naming
    it. Expect coroutine/subroutine/ephemeral/Bloom opcodes from day one.
  - Test battery: every realworld read (spliced), hardest first —
    `article_select` must yield favorites_count `I64 NOT NULL`, favorited/
    following `I64 NOT NULL`, tag_list `TEXT nullable`; LEFT-JOIN nullability;
    LIMIT/OFFSET param typing.
  - **KILL CRITERION** (timeboxed): `article_select` typed correctly, or STOP
    → pivot to decltype + mandatory alias annotations for expression columns.
    Merge only the surviving analyzer, clippy-clean.

Phase 2: Cursor FFI + reaper + microbench gate — files: `platform/Host.roc`, `platform/main.roc`, `crates/host/src/{effects.rs,router.rs,ffi_tests.rs}` — est. ~550 lines
  - **Hour zero — glue spike**: add all seven signatures, run `just glue`,
    inspect the ABI before writing implementation:
    `sql_begin! : {ctx: U64, db: Str, sql: Str, params: List(SqlValue)} => Try(U64, Str)`
    (write-capable by design — Req.roc's RETURNING), 
    `sql_step! : U64 => Try(Bool, Str)` (True = row),
    `sql_col_i64!/f64!/str!/blob! : U64, U64 => <scalar>` (coercing),
    `sql_col_type! : U64, U64 => [Null, Integer, Real, Text, Blob]`,
    `sql_columns! : U64 => List(Str)`, `sql_finish! : U64 => {}`.
  - `effects.rs`: cursor registry over raw `sqlite3_stmt` handles (module
    `cursor.rs` if it outgrows), per-conn stmt cache, ctx-tagged handles,
    ctx 0 = init-time. Params converted to owned values BEFORE arg decref
    (mirror `roc_sqlite_exec`'s obligations).
  - `router.rs`: reaper — CtxGuard moves into a spawned task awaiting the
    blocking JoinHandle; teardown never races the handler thread. Update
    ctx_registry_size expectations (e2e + ffi tests) in the same commit.
  - `ffi_tests.rs`: counting-allocator round-trips; Text/Blob param decref;
    error-path leak (begin, step to error, no finish → reaper sweeps);
    double-finish and unknown-handle = defined no-ops.
  - **GATE — microbench go/no-go**: article_select × 20 rows × 15 cols,
    cursor loop vs still-present `sqlite_exec!`, time + allocation count.
    Cursor ≥ parity on time and fewer allocs, else STOP and design a batched
    row getter before any migration.

Phase 3: Sql.roc over the cursor; migrate; then delete — files: `platform/Sql.roc`, `platform/Req.roc`, `platform/Host.roc`, `platform/main.roc`, `crates/host/src/{effects.rs,types.rs}`, all call-site files — est. ~700 lines
  - Rework `Sql.roc`: `Sql.query!(ctx, db, sql, params) -> Try(List(Sql.Row), Str)`
    — loops the cursor internally (probe via `sql_col_type!`, finish on every
    arm; handles non-escaping), pure by-name `str/i64/f64/bool/nullable_str`
    decode preserved incl. TypeMismatch + existing expects; `Sql.exec!` for
    DDL/effects-free writes.
  - Migrate incrementally, one commit per area, `just check` green each:
    `platform/Req.roc` (reserved_id! RETURNING through query!),
    realworld (`Db.roc`, `Users.roc`, `Auth.roc`, `main.roc` init!),
    `examples/e2e`, `examples/hello`.
  - **Gate: `just realworld-conformance` (154/154) here**, before deletion.
  - Separate final commit: delete `Host.sqlite_exec!`, hosted entry,
    `roc_sqlite_exec`, `execute_statement`, `SqlCell`, `sql_cell_to_roc`,
    `build_sqlite_ok`, `RocSqliteResultOk` (types.rs). Keep `checkout_sqlite`,
    `sql_param_to_rusqlite`, `decref_list_with`. `grep sqlite_exec` = empty;
    clippy clean (no dead code).

Phase 4: sqlgen scanner + emitter + gates — files: `crates/sqlgen/src/{scan.rs,emit.rs,main.rs}`, `crates/sqlgen/tests/`, `platform/NullableI64.roc`, `platform/main.roc`, `Justfile`, `.gitignore` — est. ~900 lines
  - `scan.rs`: `## @schema`, `## @fragment`, `## @sql [one]`, `## @params`;
    plain + `\\` multiline constants; `${Name}` splicing (same-module
    top-level fragments only, anything else = scan error); named `:params`
    enforced in `@sql` (error on `?`).
  - `emit.rs`: per module `X.roc` → `XGen.roc`. Reads:
    `name! : U64, Str, {params} => Try(FlatRec | List(FlatRec), [NoRows?, DbErr(Str)])`
    streaming `sql_step!` + positional getters (probe-assert on NOT NULL
    columns in debug). Writes (via `sqlite3_stmt_readonly`): pure builders
    `name : {params} -> {db, sql, params}`; RETURNING in an `@sql` write ⇒
    error (Req.roc-style flows stay on `Sql.query!`). Vocabulary:
    I64/F64/Str/List(U8); nullable → NullableStr/NullableI64/…;
    `Bool` alias annotation → JsonBool; `AS "name: Type"`/`Type?` overrides.
  - `main.rs`: `sqlgen gen <app-dir>`; `sqlgen check <app-dir>` (regen to
    `target/sqlgen-check/`, diff, nonzero on drift); gitignore the temp dir.
  - Tests: golden files AND `roc check` of golden fixtures inside
    `cargo test -p sqlgen` (goldens must stay valid Roc against the moving
    compiler); error cases: `?` placeholder, un-inferable column without
    annotation, RETURNING write, @params mismatch, unknown fragment ref.
  - `platform/NullableI64.roc` per the NullableStr pattern + expects;
    add to main.roc `exposes` (glue regen expected).
  - `Justfile`: `sqlgen`, `sqlgen-check`; wire `sqlgen-check` into `check`.

Phase 5: realworld on generated queries — files: `examples/realworld/{main,Db,Users,Articles,Profiles,Comments,Auth}.roc` + committed `*Gen.roc` — est. ~700 lines hand-written diff + generated bulk
  - Rewrite all checked queries to named `:params`; init! DDL into
    `## @schema` constants (order = apply order), init! folds `Sql.exec!`.
  - `article_select` becomes `## @fragment`; by-slug read becomes a checked
    `@sql` query on the spliced fragment; `list_articles!`/
    `run_article_page!` stay dynamic on `Sql.roc`, interpolating the same
    constant at runtime.
  - Static reads → `@sql` constants; handler writes → generated builders;
    hand decoders become thin flat-row → JSON-shape mappers
    (`split_tags`, author nesting, id-alongside) with expects.
  - Gate: `just check` + `just realworld-conformance` (154/154) +
    `sqlgen-check` clean on committed output.

Phase 6: benchmark + docs + stale-status cleanup — files: `notes/<date>-typed-sql-bench.md`, `README.md`, `examples/realworld/README.md`, `plans/2026-07-11-coeffect-effect-handlers.md` — est. ~150 lines
  - Bench per decision 10: seed harness (5k articles / 200 users / 10k
    comments), wrk, anonymous GET /articles + /articles/:slug +
    /profiles/:username, fixed conns/duration, main-vs-branch same machine.
    Bar: no endpoint regresses >2%; article-list p50 improves. Method +
    numbers in notes/.
  - Document `@schema/@fragment/@sql/@params` syntax + sqlgen workflow.
  - Fix the stale "READY FOR PHASE 1" status line in the 2026-07-11 coeffect
    plan (infra shipped).

## Testing Strategy

- Every phase: `just check` (clippy -D warnings, roc check examples,
  roc-test expects, host FFI tests, e2e) before each commit.
- Phase 1: analyzer battery in-worktree; only green survivor merges.
- Phase 2: glue-spike inspection first; leak/teardown/decref FFI tests;
  microbench gate recorded in notes/.
- Phase 3: conformance (154/154) BEFORE the deletion commit; per-area
  migration commits bisectable.
- Phase 4: golden files roc-checked in cargo test; scanner error cases.
- Phase 5: conformance + sqlgen-check on committed generated code.
- Final: grep proves no `sqlite_exec`; bench published; docs updated.
